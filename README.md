#  Car Price Analysis

A machine learning project that predicts used car prices in the UK using **Linear Regression** and classifies them into price tiers using **K-Nearest Neighbors (KNN)**.

---

##  Project Overview

This project explores a UK used-car dataset to answer two questions:

| Task | Model | Target |
|---|---|---|
| **Predict exact price** | Linear & Polynomial Regression | `log(price + 1)` |
| **Classify price tier** | K-Nearest Neighbors (KNN) | `Cheap / Moderate / Expensive` |

##  Dataset

The dataset contains UK used-car listings with the following features:

| Feature | Type | Description |
|---|---|---|
| `Make` | Categorical | Car brand (e.g. Ford, BMW, Audi) |
| `model` | Categorical | Specific model name |
| `year` | Numerical | Year of registration |
| `transmission` | Categorical | Manual / Automatic / Semi-Auto |
| `mileage` | Numerical | Miles driven |
| `fuelType` | Categorical | Petrol / Diesel / Hybrid / Electric |
| `engineSize` | Numerical | Engine displacement (litres) |
| `price` | Numerical |  Target variable (£) |

##  Exploratory Data Analysis (EDA)

- **Price distribution** — raw prices are right-skewed; `log1p` transformation normalises them
- **Outlier detection** — IQR rule applied on log-scale to avoid over-flagging high-end cars
- **Brand & fuel analysis** — countplots and grouped means reveal clear price tiers per brand
- **Correlation heatmap** — identifies numerical features most predictive of price

##  Preprocessing Pipeline

```
Raw Data
   │
   ├─ Drop nulls (low missing-value ratio → imputation not needed)
   │
   ├─ Train / Test split (80/20, random_state=42)
   │
   ├─ Log-transform y_train and y_test (after split — no leakage)
   │
   ├─ IQR outlier removal on y_train (log scale)
   │
   ├─ StandardScaler on numerical features (fit on train, transform test)
   │
   ├─ One-Hot Encoding → Make, transmission, fuelType
   │
   └─ Correlation thresholding (|r| ≥ 0.1) → drop weak features
```

### Preprocessing Decisions

- **`model` column excluded** — high cardinality (hundreds of values); one-hot encoding would add hundreds of sparse, mostly-zero columns with little signal
- **Log target** — linearises the price–feature relationship and stabilises variance for regression
- **Scaling before KNN** — mandatory; without it, high-scale features (mileage) dominate Euclidean distance

---

##  Models

### 1. Linear Regression
- Trained on `log(price)`; predictions back-transformed with `expm1()` for interpretable £ errors
- Baseline comparison: predicting mean training price for all cars

### 2. Polynomial Regression (degree = 2)
- `PolynomialFeatures` generates all interaction and squared terms
- Evaluated on same log-scale target for fair comparison

### 3. KNN Classifier
- Price buckets defined by **33rd / 66th percentile thresholds** on the training log-price (guarantees class balance)
- **12.5% std buffer** around boundaries removes ambiguous near-threshold samples
- Hyperparameters tuned via `GridSearchCV` (5-fold CV):
  - `n_neighbors`: 3, 5, 7, 9, 11, 13, 15
  - `metric`: euclidean, manhattan
  - `weights`: uniform, distance

##  Sensitivity Analysis

Three experiments test the robustness of the pipeline:

1. **Remove top correlated feature** — measures how indispensable the strongest predictor is
2. **KNN without scaling** — quantifies how much accuracy is lost without `StandardScaler`
3. **Fixed vs. percentile price thresholds** — tests whether classification is sensitive to how buckets are defined
